# ADR 001 — Language & Toolchain: C++26

- **Status:** Accepted
- **Date:** 2026-11-03
- **Deciders:** addu94 development (agent session, per BUILD PROMPT §3 — decision not to be relitigated)

## Context

addu94 is a realtime MIDI/audio song builder. The spec mandates C++26 with a
recorded fallback path, warnings-as-errors, sanitizer builds, and a rule that
exotic new language features stay **out of the audio callback**.

## Decision

**Language:** C++26, `-std=c++26` on both supported compilers.

**Verified on this machine (2026-11-03):**

| Tool | Version | `-std=c++26` | `#embed` | Notes |
|---|---|---|---|---|
| GCC   | 16.2.0 (Debian) | OK | OK | primary |
| Clang | 24.0.0 (Debian) | OK | OK | secondary / CI matrix |

`__cplusplus` returns `202400L+` under `-std=c++26` on both. No fallback to
`-std=c++2b` is needed; if a future toolchain gap appears, the fallback is
per-feature, not a global standard downgrade, and each skip is logged below.

**Build system:** CMake ≥ 3.28 (have 4.4.5) + Ninja (have 1.13.2).

**Warnings:** `-Wall -Wextra -Wpedantic -Wconversion -Werror` on first-party
code. Third-party code is exempted via `SYSTEM` includes.

**Sanitizers (CI/test targets):** ASan+UBSan on all test executables; a
separate TSan build for the lock-free queue and transport tests. Sanitizers
are never enabled on release builds.

## C++26 features actually used, and where

| Feature | Where | Status |
|---|---|---|
| `std::hardware_destructive_interference_size` | hot-path structs (SPSC queue head/tail, transport state) | used |
| `#embed` | shipping small CC0 sample blobs / default config at build time | used (GCC 16 verified) |
| `constexpr` upgrades (constexpr exception) | table-driven music math (scale/chord tables) evaluated at compile time | used |
| `std::execution` (senders/receivers) | ops layer async work (doctor/bench/report generation) — **non-realtime paths only** | deferred to M7; if incomplete in libstdc++ at that time, use a small hand-rolled task pool and record the skip here |
| `std::indirect` / `std::polymorphic` | project document ownership | deferred to M5; evaluate then, record outcome |
| Structured binding pack expansions | not yet needed | deferred |

**Hard rule restated:** the audio callback path uses plain, allocation-free,
exception-free C++ (no new/exotic constructs, no locks, no syscalls, no
logging allocations). Feature adoption is a compile-time/infra concern only.

## Rejected alternatives

- **Rust:** would satisfy safety goals but the spec fixes C++; also the
  Linux pro-audio ecosystem (ALSA seq, PipeWire native, SFZ) is C-first.
- **C++20 baseline:** loses `#embed` and interference-size; no benefit.
- **Python in the audio/MIDI path:** prohibited by spec; Python allowed for
  dev tooling only (fuzzers, report analysis) — see `tools/`.

## Consequences

- We maintain a two-compiler matrix (GCC 16 / Clang 24). Any feature used
  must compile on both, or be gated behind a CMake feature probe.
- Warnings-as-errors means compiler upgrades are code events; the CI script
  (`scripts/ci.sh`) is the gate.
