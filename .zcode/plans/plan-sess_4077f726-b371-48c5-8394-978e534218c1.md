# addu94 — More kits, more effects for keys, more features

## Context

The app currently has: 8 drum pad packs, a synth (keys) with no FX on the **live** path at all (FxChain exists only in the offline export engine), a `TrackSend` knob documented as a stored-only honest limitation (`src/app/play_engine.hpp:108-117`), no preset system, and no glide/velocity-dynamics/second-LFO on the synth. This plan delivers three things the user asked for: **more kits**, **more effects for keys** (including finally wiring FX into the live audio path), and **more features** (synth upgrades + curated presets).

Key facts from exploration that shape the design:
- `FxChain::process` (`src/audio/fx.cpp:204-288`) is a fixed per-sample sequence with a gate-flag hoist pattern; new blocks slot in there. `set_sample_rate` is the only allocating call (pre-RT); `set_params`/`recalc_` are pure math.
- Live insertion point: `PlayEngine::render_into` per-track loop (`src/app/play_engine.cpp:529-542`), after instrument render, before gain/pan. Chunk-safe (kMaxBlock), state persists as members.
- `ParamCmd`/`param_q_` SPSC pattern (`play_engine.hpp:256-263`) is the template for FX param delivery to RT.
- 4 free action ordinals exist before `tests/test_coverage.cpp:29` (`CHECK(action <= 40)`, max is 36).
- Export path needs no structural change: `render_track` copies the whole `FxParams` struct (`render_engine.cpp:90-93`); default-constructed new fields must stay bypass so exports stay bit-identical.
- Mirror pack-chip row truncates past its half-width (`controller_mirror.cpp:269`) — 16 packs would lose chips; needs a two-row wrap.
- `tests/test_sampler.cpp:682-694` hardcodes pack count 8 and names.

## 1. More effects for keys

### 1a. Five new DSP blocks in `src/audio/fx.hpp/.cpp`
- **Reverb** — standalone `Reverb` class (Schroeder: 4 combs + 2 allpass per channel; compact rings, size/decay scaled), also used as an insert block inside `FxChain`.
- **Compressor** — per-channel envelope follower; threshold/ratio/makeup.
- **Bitcrusher** — bit-depth quantize + sample-hold downsample.
- **Flanger** — modulated short delay (5 ms ring) with feedback.
- **Tremolo/AutoPan** — LFO amplitude modulation, stereo phase offset.
- **Drive shapes** — `drive_shape` enum: soft tanh (existing), hard clip, foldback.
- New signal flow (documented in header): EQ → comp → crush → drive → chorus → flanger → delay → tremolo → reverb.
- Contract preserved: rings allocated only in `set_sample_rate` (once, pre-RT); all new params default to bypass/off so default `FxParams` stays bit-identical; clamps in `set_params`; gate flags hoisted in `process`.

### 1b. Live FX path in `src/app/play_engine.hpp/.cpp`
- Per-track `FxChain fx_chains_[4]` + app-side truth `fx_params_[4]`; `FxParamCmd{track, FxParams}` on a new SPSC `fx_q_` (mirrors `param_q_`), drained in `render_into` before mixing.
- Each track's chain processes in the mix loop after instrument render, before volume/pan. Drums get FX too (glue kit EQ/delay).
- Tempo-synced delay: `render_into` reads the transport tempo atomic per buffer and calls `fx.set_tempo` when it changes (alloc-free ⇒ RT-safe; documented in fx.hpp — `set_sample_rate` remains pre-RT only).
- **`TrackSend` knob becomes real**: it now sets the selected track's reverb amount (`fx_params_[t].reverb_mix`, pushed via `fx_q_`); the `track_send_` atomics stay as UI readout, updated in sync. Honest-limitation comments replaced with the real story.
- Public getters/setters for UI: `track_fx_params(track)`, `set_track_fx_params(track, FxParams)`.

### 1c. FX control: hardware + UI
- 4 new actions in `src/mapping/actions.hpp`: `FxSelect` (cycle FX slot), `FxToggle`, `FxParamA`, `FxParamB` (slot-dependent params).
- **Edit-mode knob page becomes the FX page**: 1 FxSelect · 2 FxToggle · 3 FxParamA · 4 FxParamB · 5 tempo · 6 loop · 7 quantize · 8 master. (Replaces ScrubCoarse/Fine — stored-only no-ops today — and ClickLevel, which already has a UI slider on the transport bar.) Play-mode knobs unchanged.
- Sync trio updated: `mapping.cpp` edit_actions table, `audit.cpp` coverage rows, `controller_mirror.cpp` kEditLabels; `test_coverage.cpp` ordinal check bumped 40 → 47 with a comment (headroom).
- New `FxPanel` widget (`src/ui/fx_panel.hpp/.cpp`): bottom row next to the controller mirror — 9 slot chips, selected slot toggle + two drag lanes, **preset chips**. Uses `theme.hpp` primitives (draw_panel/draw_well); wired in `main_window.cpp` constructor + `tick()`.

## 2. More kits: 8 → 16

- 8 new `PackSpec` rows in `src/audio/drum_kit.cpp` (parameter tables over the same deterministic recipes): **Acoustic, Linn 80s, DnB, Dub, Ambient, Electro, Garage, Breaks**. `kPackCount` → 16 (the single-constant design makes this one number + 8 table rows).
- Mirror: pack chips wrap to two rows so all 16 are clickable (fixes the truncation).
- Update `tests/test_sampler.cpp` pack test (count, names, out-of-range check); MANUAL.md pack table.

## 3. More features for keys

### 3a. Synth upgrades (`src/audio/synth.hpp/.cpp`)
- **Glide/portamento + mono-legato** (`glide_seconds`, `mono_legato` params; per-voice pitch ramp state in `Voice`) — bass and lead essentials.
- **Velocity → filter** (`velocity_filter` 0..1) — velocity opens the cutoff.
- **LFO2** — second routable LFO (Filter/Pitch/Amp targets, rate, depth) alongside LFO1.
- All follow existing patterns: params in `SynthParams` with clamps in `set_params`, per-voice state in `Voice`/`VoiceExt`, no allocation in RT.

### 3b. Curated track presets
- `TrackPreset` table in `PlayEngine` (~10: Default Saw, Acid Bass, Warm Pad, Pluck Keys, Square Lead, Sub Bass, Dreamy Keys, Stabs, Lo-Fi Keys, Fly Lead) — each a `{name, SynthParams, FxParams}` combo exercising the new blocks.
- API: `preset_count()/preset_name(i)/apply_preset(i)` + new `track_synth_params(track)` getter; preset chips on FxPanel apply to the selected keys track (no-op on Drums — packs are the drum presets).

## Risks / decisions to be aware of
- Edit-mode ScrubCoarse/Fine/ClickLevel knob bindings are **removed** (they were stored-only/no-op; scrub getter stays for the future transport milestone). ClickLevel remains on the transport-bar UI slider.
- FX params are session-level (like synth params today — the project document stores only clip events), so no JSON schema change is needed.
- Tempo changes cause a delay-length recompute mid-stream (rare knob action; documented, matches existing offline behavior).
